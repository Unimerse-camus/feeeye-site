# FeeEye 自动化运营推广完整方案

> 日期：2026-08-31。状态：规划稿，未开启新自动化、未配置账号权限、未发布社交内容。
> 约束：免费获客优先、不新增付费推广或订阅、不安装来源不明的软件；自动化不能绕过平台规则、地区限制或人工审批。

## 1. 总体决策

推荐“自动生产与检查 + 人工审核与社交发布 + 自动汇总复盘”，而不是无人值守群发。

FeeEye应自动化的是搜集证据、核对数据、计算、生成图表、整理稿件、部署验证、抓取通知和周报。应由人负责的是判断信息是否适用、批准新结论、处理用户疑问、选择平台账号、授权数据访问和确认公开发布。

第一期目标是使一次1000 USDT费率研究产生一套一致的中英文页面、PNG/SVG图、短帖、视频脚本与来源清单。不是追求文章数量或发帖数量。

免费渠道排序：Google/Bing搜索 → X原创内容 → YouTube搜索型演示 → Reddit等社区人工回答。Telegram/RSS用于后续留存，不把新建群当冷启动获客来源。

## 3. 免费与全自动之间的现实边界

### X

X API采用按量付费。零新增预算方案不依赖其读写API，也不把浏览器脚本当免费替代发布接口。官方规则禁止脚本化X网页等非API自动化；AI自动回复机器人还需事先获得X明确书面许可。

因此：自动生成原创帖与图，人审核后手动发布；如果当前账号提供原生排程，则由人设置排程。关键词自动搜人、自动评论、自动点赞和批量私信不进入方案。[X API定价](https://docs.x.com/x-api/getting-started/pricing)、[X自动化规则](https://help.x.com/en/rules-and-policies/x-automation)

### Reddit

不建设未经批准的商业爬虫或自动回帖机器人。Reddit API访问需要审批，商业数据使用还需明确书面批准。没有许可时，由运营者人工选择问题，自动化只处理获得授权的输入和FeeEye自己的事实材料；公开发布由人完成，并遵守各社区规则。[Reddit Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy)

### YouTube

一期采用自动生成脚本、字幕和素材清单，人工录屏、检查最终视频，通过YouTube Studio上传和原生排程。二期才评估官方Data API与OAuth授权。未审核API项目上传的视频可能被限制为私密，不承诺申请即能自动公开发布。[YouTube原生排程](https://support.google.com/youtube/answer/1270709)、[Videos.insert限制](https://developers.google.com/youtube/v3/docs/videos/insert)

### Google与Bing

Google Search Console API用于效果与索引状态读取，不把URL Inspection当作请求索引接口。普通FeeEye文章不能使用仅适用于招聘和直播页面的Google Indexing API。Google依靠可抓取内链与sitemap；人工请求仅用于少量重点页，不绕验证码和配额。[URL Inspection API](https://developers.google.com/webmaster-tools/v1/urlInspection.index/inspect)、[Indexing API适用范围](https://developers.google.com/search/apis/indexing-api/v3/using-api)

Bing及参与搜索引擎采用部署成功后的IndexNow变化通知。受理、抓取、索引、曝光、点击分别记录，不能把HTTP 200写成“已收录”。

## 4. 系统结构

```text
官方费率/规则 + GSC查询 + 人工筛选的用户问题
                    ↓
           候选事实与证据库
                    ↓
         口径、时效、计算、风险校验
                    ↓
          内容包：网页/图/短帖/脚本
                    ↓
              人工审批关口
              ↙          ↘
     网站受控发布        社交人工发布/原生排程
              ↘          ↙
        发布回执 + 访问/搜索/互动汇总
                    ↓
          周报 + 下周选题候选
```

一个阶段失败，依赖它的阶段停止。来源获取失败不能用零值、旧截图或模型猜测补齐；发布结果不确定不能直接再发一次。

## 5. 上线自动推广前的P0修正

以下为本轮本地代码检查发现的真实风险，优先级高于排程发帖：

1. **更新日期分开。** `fetch_exchange_meta.mjs`会刷新所有交易所的`last_updated`，但不等于全部费率重新核验。分离`retrieved_at`、`verified_at`、`effective_at`和行情更新时间。
2. **Benchmark历史快照化。** 当前表格读取可变EX数据，标题日期、结论和社交稿部分写死。必须冻结一份事实JSON，让页面、图表、CSV和社交稿全部引用同一版本；改事实即取消旧审批。
3. **纠正“实测”口径。** 当前内容是公开费率核算，不是真实成交实验。统一改称“公开费率对比/核算”，不能声称完成交易或测得实际成交总成本。
4. **修正条件数字。** Coinbase若只确认费率上限，不能同时给出确定的扣费后金额；USDT等值费用不一定从USDT余额扣除。图表必须显式保留范围、计价和产品差异。
5. **Sitemap时间真实。** 当前每次生成把所有`lastmod`设为当天。应按正文/数据实质变化更新，避免无变化页面伪装成新内容。
6. **资产不可变版本。** 图表改内容需生成新版本文件名，避免一年immutable缓存让旧图配新结论。Logo保留统一源文件。
7. **统计事件不夸大。** `learn_article_complete`当前仅代表来源区进入视口，应叫`article_end_view`；`tool_use`只是首次互动，不等于成功计算。新增结果成功事件后才谈任务完成率。
8. **UTM真正白名单。** 当前仅清洗字符，不保证值无个人信息。改为渠道枚举和预注册campaign ID，未知值不发送。
9. **发布门禁。** 当前main推送同时触发验证和部署，不应仅凭“有CI”认定发布已被保护。候选修改先走PR/预览，必过检查和批准后才合并。

## 6. 八条工作流

### W1：站点与数据健康检查

- 触发：每日北京时间09:17；发布后额外运行一次。时间为拟定起点，不是流量最佳时段结论。
- 输入：首页、学习页、benchmark、3个主工具、sitemap、关键资产和最近工作流状态。
- 自动执行：HTTP检查、关键内容断言、站内链接、生成器/数据契约、来源访问状态、最后成功时间。
- 输出：一份健康摘要；仅异常发通知。
- 失败处理：保留最近通过版本，不覆盖正常数据；外部来源403/登录墙标“待人工核验”，不突破访问限制。

### W2：官方费率/规则变化检测

- 触发：每日低频检查已允许访问的官方来源；每周人工复核高风险字段。
- 保存：来源URL、适用实体/地区/产品/档位、有效日期、观察值、短证据摘录、内容哈希、解析器版本。
- 自动执行：比较候选差异，忽略导航和广告噪声，生成“旧值—新值—来源”审阅单。
- 输出：候选数据PR，不直接改main。
- 门槛：任何交易费、KYC、地区限制、返佣条款变化必须人工确认；网页200不等于事实确认。

### W3：选题队列

- 触发：每周一09:37。
- 输入：GSC查询与页面汇总、人工提交问题、官方规则变化、既有内容缺口。
- 自动执行：合并重复问题，生成最多5个候选选题。
- 人工决定：仅选择1个主选题。优先费用/转账/平台适用性问题，不追币价热点。
- 一期不自动抓取Reddit/X，不把购买API视作免费。

### W4：内容包生成

- 触发：选题与事实版本获批后。
- 每包：中英文网页草稿、公式/假设、来源表、CSV、SVG和PNG分享图、3条X候选文案、1个YouTube脚本、适合人工回答的论点清单。
- 程序负责所有算术、数值、百分比和图表；模型只负责表达和结构，不能创造数字、法律结论或来源。
- 一期采用确定性模板。需要模型润色时在已授权的交互流程中完成；无人值守模型API没有预算或权限时禁用。
- 数值提取、双语一致性、排除项、字符长度、链接和图片尺寸均做自动测试。

### W5：审批队列

- 每条内容显示：目标账号、语言、正文、最终图片、落地页、来源日期、UTM、商业披露、拟发布时间和风险标记。
- 状态：`draft → evidence_ready → reviewed → approved → scheduled → publishing → published → verified`。
- 分支状态：`blocked`、`expired`、`failed`、`needs_reconciliation`。
- 审批绑定正文、图片、落地页和事实版本的哈希；任一改变必须重审。
- 新文章、新结论和社交发布都需要确认。日常数值刷新只有在明确授权字段/来源/范围后才能自动合并。

### W6：网站发布与搜索通知

- 触发：审批完成且CI通过。
- 自动执行：合并受控变更、构建、等待Cloudflare部署、核对预期commit/内容哈希、HTTP与双语页面检查。
- 线上确认后才发布社交材料或提交IndexNow。
- 只提交新增/变更/删除URL，不每天重复推送整个站点。
- 429按服务端提示退避；403区分验证等待与权限问题；422先修负载；不确定响应先核对状态。
- Google每周只读检查重点页，sitemap和内部链接负责发现，不建设批量点击GSC的机器人。

### W7：免费渠道分发

| 渠道 | 自动部分 | 人工部分 | 一期节奏 |
|---|---|---|---|
| 网站/SEO | 草稿、计算、图、内链候选、部署与IndexNow | 审批新事实和文章 | 每两周1份benchmark；交替周更新教程 |
| X | 3条草稿、PNG、UTM与披露检查 | 选择账号、确认、人工发布或原生排程 | 每周2–3条，不重复贴图灌水 |
| YouTube | 脚本、分镜、字幕草稿、缩略图文字 | 录屏/旁白、检查最终视频、Studio排程 | 前月每两周1条3–6分钟视频 |
| Reddit/论坛 | 自有事实库准备论点和来源 | 查版规、选问题、写针对性回答、发布 | 每周3–5个有帮助的回答；不设强制带链接配额 |
| RSS | 文章获批发布后更新feed | 初始模板与授权 | 仅真实更新 |
| 自有Telegram频道（二期） | 已批准内容按频道排程 | Bot权限、频道确认、内容批准 | 每周1份汇总，不向陌生群或私信推送 |

未通过官方许可与权限核验的渠道，发布模块默认关闭；账号登录的人工浏览器会话不作为无人值守凭据。

### W8：效果周报与反馈

- 每周日18:17生成周报，附各数据源实际覆盖日期和缺失标记。
- GSC：非品牌曝光/点击、查询、页面和索引变化。使用最小只读OAuth权限；未授权则人工导出。
- Cloudflare：访问/页面/来源等已提供聚合指标；明确EU排除口径。能否经API取数取决于账号权限，不能假设已有Token。
- X/YouTube：先用各平台原生统计和人工录入，不因报表自动化购买API。
- affiliate：只导入后台聚合点击、注册、佣金，不收集用户身份或关联站内个人轨迹。
- 每条内容在发布后约24小时、7天、28天做汇总。缺数据留空，不记为0。
- 自动提出最多3个下周实验；不自动提高发帖频率、修改返佣比例或承诺收益。

## 7. 推荐技术栈与目录

复用GitHub Actions、现有Node静态生成器、Cloudflare Pages及现有图像运行库。暂不新增n8n服务器、付费排程工具、多Agent调度平台或未知扩展。

拟新增结构（仅方案，本轮未创建）：

```text
ops/automation/
  config.json                 # 允许来源、渠道开关、限额、紧急停止
  sources.json                # 事实来源与适用口径
  campaigns.json              # 注册UTM活动，不接收任意文本
  snapshots/                  # 获准公开的冻结数据与版本
  content/                    # 草稿与发布包
  reports/                    # 可公开的方法/汇总；私有数据另存
build/ops/
  monitor.mjs
  collect_source_changes.mjs
  build_content_pack.mjs
  validate_content_pack.mjs
  verify_deployment.mjs
  submit_changed_urls.mjs
  build_weekly_report.mjs
```

OAuth Token、账号数据、私有报表和错误原文不提交到公开仓库。只在私有Secrets/存储中保存，输出做脱敏。公开网页或PDF的全文抓取副本不直接再发布。

GitHub定时任务可能延迟，高负载时可能丢弃，公开仓库长期无活动也可能停用排程。选非整点执行，记录最后成功时间；24小时未成功时提示人工补跑，不能把本地电脑或聊天窗口视为24小时服务器。[GitHub排程限制](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows)、[工作流触发规则](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)

## 8. 发布安全与失败恢复

- 总开关：`publishing_enabled=false`为默认值；每个渠道独立开关。
- 幂等键：`campaign_id + channel + locale + approved_version`。人工发布也记录帖子ID/网址；没有API确认时不编造成功回执。
- 一次授权不覆盖正文改变、账户切换、收件人改变、增加付费或扩大权限。
- 登录过期、验证码、额度不足或账号被限流：停止相应渠道，不切账号、代理或网页脚本绕过。
- 无来源/来源冲突/数据过期：进入人工审核，不生成带数值的已批准稿。
- 线上部署未确认：不推社交、不提交变化URL。
- 发布超时且状态不明：先核对是否已发，再决定重试，禁止重复发布。
- API/配额错误采用有限退避；超过配置次数只通知一次，防止告警风暴。
- 发现事实错误：暂停关联排程，修订网页并附更正说明；删除已发布内容须另行批准。
- 回滚：保留最近通过的数据快照和构建版本，以新回滚提交恢复，不强推或删除历史。
- 新依赖固定版本和来源，Actions使用最小权限；发布密钥不提供给抓取或内容生成步骤。

## 9. 成本与人工投入

“免费渠道”指没有广告投放，不代表全部运作零成本。

| 项目 | 一期预算原则 |
|---|---|
| 广告、买粉、买外链 | 0，禁止 |
| 新SaaS/排程订阅 | 0 |
| X API | 不启用付费读写 |
| 新模型API | 默认0，不将现有聊天订阅当免费API额度 |
| CoinGecko | 现有工作流使用Pro；沿用已有授权与限额，不声称数据采集免费 |
| GitHub/Cloudflare | 沿用现有服务，在账号实际免费额度内运行；未验证额度前不启用付费超额 |
| 人工 | 目标每周2–4小时文字审核/分发/复盘；每条视频额外1–2小时录制检查 |

若必须完全无人值守地发布到X，必须另批官方API预算和账号授权；不能同时承诺零新增预算、完全无人值守、全渠道覆盖。

## 10. 统计与验收

一期先看真实可获得指标，不给不存在的自定义事件补数字：

1. 搜索：有效收录情况、非品牌曝光和点击、落地页。
2. 网站：页面访问与来源；Web Analytics不是Zaraz自定义事件存储。
3. 行为：事件接收端尚未确认时，任务完成率显示“未接通”。第二阶段另行批准无Cookie第一方聚合接收方案，核实费用、保留、日志与地区要求后才启用。
4. 社交：发布数量只作过程指标，关注实际落地访问和有意义的问题。
5. 商业：affiliate后台聚合注册和佣金，注明归因窗口，不能把不同平台数字直接拼成个人漏斗。
6. 效率：每渠道有效访问或结果事件数/人工小时；事件数不等于去重用户数。

建议的运行验收门槛（工程目标，不是市场预测）：

- 100%带数值内容能追溯到已批准事实版本。
- 0条未经批准的社交发布、0次越权、0个禁止字段。
- 0次重复发布，失败均有状态和可恢复路径。
- 所有已发布页面、图表和脚本数值一致。
- 私有数据与凭据不进入公开仓库、日志或内容提示。
- 前4周不承诺流量/收入；以28天窗口看趋势，渠道样本不足时只给方向性判断。
- “每渠道30访问”仅为初步观察门槛，不是统计显著性或放大量化依据。

## 11. 30天实施顺序

### 第1周：先修可信度与发布门禁

- 完成第5节P0修正。
- 冻结1000 USDT benchmark事实版本，自动生成页面/图/CSV/文案。
- 添加内容队列、禁用默认发布、审批哈希和CI检查。
- 核实Cloudflare/GSC现有权限；不创建新付费服务。

### 第2周：全链路只生成不发布

- 跑健康检查、来源变化、候选选题、内容包、周报。
- 用假回执测试去重、限流、失败恢复和紧急停止。
- 人工抽查至少3个内容包，确认中英事实、图表和来源一致。

### 第3周：小规模人工批准发布

- 网站1次受控更新；X每周2–3条；社区3个有帮助的回答。
- 做1条YouTube视频，使用原生Studio排程。
- 每条记录最终发布网址与批准版本，复核24小时/7天效果。

### 第4周：复盘后再扩大自动化范围

- 按实际人工耗时、错误率、有效访问与反馈比较渠道。
- 优先增强最有效的两条流程，不先扩大账号或帖量。
- 若重复需求已出现，再启用RSS/自有Telegram频道。
- 若任务事件价值明确，再决定隐私合适的接收端，不自动接入GA4。

## 12. 下一步建议

先交付一个可验收的小系统，而非一次搭完全部平台：

> 冻结事实JSON → 自动生成中英页面、PNG/SVG、CSV和3条短帖 → 自动校验 → 人工批准 → 网站部署 → IndexNow变化通知 → 周报。

第一批只围绕1000 USDT现货费用，不扩合约、不做喊单、不自动回复陌生人。跑通两轮后再决定视频和社群自动化是否值得建设。
