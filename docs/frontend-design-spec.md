## 〇、项目背景与硬约束

| 维度 | 我们的实际情况 | 对设计的约束 |
|---|---|---|
| 目标用户 | 海外华人 + 国际加密用户（**非中国大陆/港/美/新等受限区**） | 视觉语言国际化、双语（en + zh）、币圈术语 |
| 站点类型 | **零依赖静态站**（vanilla JS + 零构建） | 不能用 Tailwind、不能跑 SSR；CSS 全部 inline |
| 商业模式 | 工具站 + 返佣（KuCoin 为唯一 affiliate） | CTA 不打扰、不假装、明确披露 |
| 流量结构 | SEO 长尾 + GEO 引用 + 移动优先 | 移动端是默认、Core Web Vitals 是底线 |
| 性能预算 | Pages 边缘缓存后 300 页全部静态 | JS 极简、字体系统字体优先、不上 webfont |

## 一、设计原则（5 条铁律，全部采纳）

| # | 原则 | 我们怎么做 |
|---|---|---|
| 1 | **工具优先，内容让路** | 首页首屏只有工具，无 hero 大图/无营销文案；4-5 个工具卡片即第一屏 |
| 2 | **三步内完成核心任务** | 计算器 = 输入金额 → 选通道 → 看结果；没有"提交/登录/跳转" |
| 3 | **结果可视化优先于文字** | 大数字 + 颜色（绿/红）+ 「← 最便宜」徽章，不用段落文字 |
| 4 | **移动端是默认，桌面端是增强** | `@media(max-width:640px)` 单列；输入区/结果区移动端上下，桌面端左右 |
| 5 | **返佣 CTA 不打断、不欺骗** | CTA 出现在用户"拿到结果后"，永远带 disclosure 和 `rel="sponsored"` |

**我们当前亮色板（CSS 变量）**：

```css

  --bg: #f7f8fa;     /* 背景 */
  --card: #fff;        /* 卡片 */
  --ink: #1c2430;      /* 文字-主 */
  --sub: #5b6776;      /* 文字-次 */

  --bad: #dc2626;      /* 危险 */

```

**配色原则（一页一主色）**：蓝做信息呈现，绿/红只用状态数据，不做渐变、不堆颜色。

**对原规范的优化**：
- 我们保留了 `--brand2` 副色（青绿 `#0ea5a4`）用于 sticky 渐变按钮（吸引点击 + 视觉锚点）。这是因为我们的 CTA 只有"Open KuCoin"一个入口，副色帮助它在页面里被注意到。
- 橙（`--warn`）作为辅助状态色（提示用户"为什么没结果"等），原文档没列但我们用得到。

### 2.3 间距系统（8px 基准）

| token | 值 | 用途 |
|---|---|---|
| xs | 4px | 极小间隙 |
| sm | 8px | 紧凑（按钮内 padding 之一） |
| md | 16px | **基准间距**（卡片内 padding） |
| lg | 24px | 区块间 |
| xl | 32px | 大区块 |
| 2xl | 48px | Hero / 极端 |

**我们当前落地**：
- 卡片：`padding: 14px 16px`（≈md）
- 表格 cell：`padding: 10px 12px`
- 页脚：`padding: 22px 18px 60px`

**对原规范的优化**：
- 我们的卡片 padding 是 `14px 16px`（接近 md），比规范建议的 16px 略小。保留，因为——让保留——卡片更紧凑紧凑、信息密度更高（（用户扫表更快）。

## 四、动线设计（重点）

### 4.1 主转化动线（工具 → 返佣）

```
用户进入工具页
  ↓ 输入金额（自动重算）
  ↓ 选择入金通道（下拉，筛选可支持通道）
  ↓ 看到结果（7 所对比，最低高亮，节省提示）
  ↓ 在结果区行内 CTA 出现 → 注册 KuCoin
```

**3 条动线要点**（采纳原规范）：
1. **结果实时更新**——输入完就出结果，不需要"提交/计算"按钮（mobile-friendly）
2. **CTA 位置固定**——永远在结果区下方 + sticky 底部，绝不浮窗、不弹窗、不遮挡
3. **CTA 内容场景化**——基于用户刚算的结果定文案（"Open KuCoin →" 而不是"立即注册！限时优惠！"）

### 4.2 单一路径原则

每个工具页只设计**一条主路径**，不分叉——避免"介绍/教程/博客/工具"四不像。

### 4.3 不打断流程

- **无强制弹窗**（注册、订阅、Newsletter、Cookie 同意横幅——除非真合规需要）
- **无强制注册**（不登录也能用所有工具）
- **无广告打断**（页面内不放与工具无关的横幅）

## 五、布局规范

**移动端单列**：

[输入区]      ← 顶部（输入框、通道、价差）
[计算结果]    ← 下方（大数字 + 表格）

**桌面端双列**：

```
[输入区]    │  [计算结果]    ← 左输入右结果，井排对比
            │
            │  [CTA 卡片]    ← 结果下方
```

### 5.2 布局要点（采纳）

- **移动端**：拇指友好，输入在上、结果在下、CTA 在底
- **桌面端**：输入在左、结果在右、并排对比
- **结果区视觉突出**：背景区分 + 大数字 + 语义色（绿/红）

## 六、组件规范

### 6.1 输入框

```html
<input type="number" inputmode="decimal" pattern="[0-9]*" 
       class="num" placeholder="1000">
```

要点：
- 数字输入用 `type="number"` + `inputmode="decimal"` + `font-size: 16px`（防 iOS 放大）
- 等宽数字 `font-variant-numeric: tabular-nums`
- 高度 48px（触控目标 ≥44）
- 边框 1px var(--line)，聚焦 2px var(--brand)

### 6.2 结果展示（核心组件）

```
┌─────────────────────────────────────────────────┐
│  [交易所]  [入金费]  [交易费]  [提现]  [价差]  [总成本]  [CTA]  │
│  Binance   36–41     1         —       1       37–41     Sign up│
│  KuCoin    25–35     1         —       1       26–36   ←最低 │
│  Kraken    38–50     4         —       1       42–54    Sign up│
└─────────────────────────────────────────────────┘
💡 最便宜（KuCoin）比最贵（Kraken）约省 16 USDT（取区间中值）
```

要点：
- 最低行 `outline: 2px solid var(--ok)` 高亮
- 区间用 `–` 分隔（en-dash），不是 `-`
- 比较行用 `<span class="best">← 最低</span>` 徽章
- 大数字 40px，tabular-nums 等宽

### 6.3 CTA 按钮（返佣转化）

**形态**：
- 表格内：`<a class="cta">Sign up</a>`（小按钮）
- 底部 sticky：渐变背景（`linear-gradient(135deg, #1e3a8a, #0ea5a4)`）+ 白色按钮

**三原则**：
1. 文案场景化：`Sign up` / `注册` 而非"立即开户！限时优惠！"
2. 不打断：CTA 出现在结果下方，不抢用户看结果的注意力
3. 不欺骗：永远 `rel="sponsored nofollow"` + 页面底部 disclosure

### 6.4 表格（对比类工具）

- 边框 1px var(--line)，行高 ~10px 12px padding
- 表头 `#f1f5f9` 浅灰
- 数字列 `tabular-nums` 等宽
- 支持横向滚动（移动端表格过宽时）

### 6.5 标签/徽章

- 价格变化、最新、热门等用 6px 圆角徽章
- 颜色语义：涨=绿、跌=红、中性=蓝
- 字重 700，12-13px

### 6.6 图表（采纳）

- 库：Recharts / Chart.js（二选一）
- 大数字 + 颜色 + 图表，不光看一段文字
- 渐变填充，最低 3 套数据维度对比
- 移动端单列，卡片高度 280px，引入视口后再渲染

## 八、暗色模式（**优化决策：默认亮色 + 切换 + 尊重系统**）

> 原规范建议**默认暗色**（依据"80% 加密交易者夜间使用"）。
> 我们做**优化调整**：**默认亮色 + 提供暗色切换 + 尊重系统偏好**。

**理由**：
1. **目标用户构成**：海外华人 + 国际币圈用户，**很多是新手**（白天学习、看行情）。暗色对新手**阅读门槛更高**（数字小、对比度差）。
2. **SEO/GEO 友好度**：浅色站点在搜索引擎抓取预览、移动端浏览器默认渲染、ChatGPT/Perplexity 引用截图中**更清晰可读**。
3. **专业感**：KuCoin/Binance 等头部交易所是**亮色默认 + 暗色可选**，我们跟随主流。

**实施**：
```css
/* 1. 尊重系统偏好（但我们的默认仍是亮色） */
:root { /* 默认亮色变量 */ }
@media (prefers-color-scheme: dark) {
  :root { /* 暗色变量覆盖 */ }
}
/* 2. 手动切换（未来） */
:root[data-theme="dark"] { /* 暗色变量 */ }
```

**当前状态**：✅ 颜色变量已分离（亮色在用），暗色色值已定义在数据表（§2.1），**未做自动切换**。优先级 P3 阶段实施。

## 九、性能规范（前端）

### 9.1 性能指标（采纳）

| 指标 | 目标 |
|---|---|
| LCP | **< 1.5s** |
| TTFB | **< 300ms** |
| CLS | **< 0.05** |
| 首屏 JS | **< 100KB** |
| 首屏 HTML | **< 200KB** |

### 9.2 实现要点（采纳）

- **工具页静态渲染**（SSG/ISR），**无客户端 JS 计算**
- **计算逻辑放客户端**（纯函数，秒算）
- **图表懒加载**（进入视口后再渲染）
- **图片用 SVG/WebP**
- **字体用系统字体**（不加载 webfont；或只加载 Inter 一个）

用 Cloudflare Web Analytics 的 **Core Web Vitals** 面板（LCP/INP/CLS）作为 baseline。
