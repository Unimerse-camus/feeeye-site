# FeeEye 自动化运营第二十阶段：用户反馈驱动的内容改进

日期：2026-09-04。目标是让用户反馈可以主动进入网站内容改进队列，但不允许一条评论或少量点击直接改写页面。

每篇中英文学习文章末尾新增结构化反馈控件。用户可选择“有帮助”，或在“需要改进”后选择表述不清、缺少步骤、可能过时、链接有问题、其他内容问题。控件不包含自由文本、邮箱、账号或用户 ID；事件属性使用硬编码白名单，非注册文章或分类会被前端拒绝。

`feedback_improvement_queue.mjs` 为加密汇总数据准备了确定性分析合同：完整覆盖8个主题的中英16条记录，拒绝自由文本和任意字段。普通改进候选需要至少5份反馈、其中至少3份负向且负向比例至少40%。同一页面至少2次链接错误或内容过时反馈可进入紧急复核，但仍必须核验一手来源。

改进候选必须同时检查中英文对应页、当前实验冲突、来源时效和部署版本。用户反馈只是需求证据，不是事实来源。自动改页和自动发布仍为 `false`。

Cloudflare 官方支持通过 Zaraz `track()` 发送自定义事件，并通过 GraphQL Analytics API 的 `zarazTrackAdaptiveGroups` 读取监控数据。本阶段先增加只读、零数据行的 schema 探测，确认实际账号可用的事件维度和过滤字段后，下一阶段再实现28天加密聚合采集器，不根据文档猜测字段名。
