# FeeEye 工具库规划（Tools Roadmap）

> 目标：围绕币圈用户「算账 / 查数据 / 找交易所」的真实需求，建设**工具矩阵**作为站点的流量引擎与转化层，
> 每个工具 = 免费价值 + 场景化 KuCoin CTA，与程序化 SEO 页面（where-to-buy / compare / country）互相导流。
> 数据统一来自 `data/` 真相源（7 所官方费率 + CoinGecko 币种），中英双语（en / zh），零后端纯前端。

## 三、统一架构规范（每个工具必须满足）

1. **单文件纯前端**：`tools/[tool].html` + `tools/[tool].zh.html`，vanilla JS，`window` 数据层（`../data/*.js`），零构建。
2. **中英双语**：zh 版 = 完整翻译（标题/标签/按钮/结果表/披露），页头带语言切换链接。
3. **CTA 规则**：
   - 结果区行内 CTA：用户刚拿到有价值结果时展示（信任峰值）
   - 底部 sticky：KuCoin 注册条（仅非受限地区显示，JS 地区过滤）
   - 一律 `rel="sponsored nofollow"` + 页面 disclosure
4. **地区合规**：内置 country 过滤（沿用 fee-calculator 模式），受限地区隐藏全部 CTA。
5. **页面互链**：
   - 工具 → where-to-buy / compare 页（数据延伸）
   - 首页卡片 → 各工具
   - sitemap 不含 tools（tools 是功能页，不进 SEO 索引流）
6. **数据时间戳**：显示 `last_updated`，注明"数据快照，交易前请核实"。

| 阶段 | 内容 | 验收标准 | 预计 |
|---|---|---|---|
| ① | T1 盈亏计算器（en+zh） | 可计算、CTA 正常、地区过滤生效、0 死链 | 1 天 |
| ② | T2 合约清算计算器（en+zh） | 同上 | 1 天 |

> 与 A2（扩币 500+）并行不冲突；工具全部复用数据层，扩币只影响数据文件。

## 五、与「页面优化」的衔接

工具库就绪后做**页面优化**，重点：
1. 首页改版：工具矩阵卡片分组展示（算账类 / 数据类 / 查询类），热门币区保留
2. 币页增强：加「相关工具」区（如 BTC 页 → 盈亏计算器 / 提币对比）
3. 移动端体验（卡片布局、表格横向滚动）
4. 首页/工具页标题与描述打磨（SEO + GEO）
