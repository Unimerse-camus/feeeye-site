# FeeEye 自动化运营第二十五阶段：用户反馈统一编排

日期：2026-09-04。Phase 21至24已完成反馈聚合、改进队列、修订证据计划、内容诊断和官方链接证据。原实现使用四个独立cron和四个开关，存在上游延迟时下游读到旧回执的风险。

`feedback-operations.yml` 将全链路收敛为单一runner内的固定顺序：

1. 生成当前中英页面inventory。
2. 读取Cloudflare Zaraz固定28日反馈聚合。
3. 生成加密改进队列。
4. 绑定当前build和中英页面hash，生成加密修订计划。
5. 生成加密内容结构与证据路由诊断。
6. 仅在诊断要求时检查已注册官方链接。
7. 全部成功后一次性提交完整加密周期。

任一步失败时，后续步骤停止，且不向 `automation-receipts` 推送半套周期。所有详细仍使用 AES-256-GCM 加密；唯一明文artifact是不含指标和页面的采集摘要。

回执身份不能只绑定数据窗口和build。工作流或文档变更可能不改变站点build，但仍会改变Git revision。因此修订计划与诊断文件名同时绑定窗口、build和revision指纹；链接证据再额外绑定实际检查时间。旧格式回执仍可读，新记录不会覆盖或与旧记录冲突。

统一流程只使用 `FEEEYE_FEEDBACK_AUTOMATION` 一个总开关。运行前会检查四个旧开关；任一旧开关为 `enabled` 都立即拒绝执行，避免重复采集和并发写入。

统一工作流的候选调度为每周一 03:07 UTC。总开关未创建前仍保持关闭；手动运行可用于验证整个加密链路，不会启用定时、自动改页、自动建PR或发布。
