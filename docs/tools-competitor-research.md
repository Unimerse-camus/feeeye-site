# 工具竞品调研 + 差异化方案（盈亏 / 清算计算器）

> 开发前调研（2026-08-12）：先看市面上已有的工具、它们的问题，再决定我们怎么做。
> 结论先行：**竞品要么"简单到无多所对比、无精确费率"，要么"复杂到要登录/连账户"——中间地带（免费、精确多所费率对比、双语、带转化场景）是空白的，这正是我们的位置。**

---

## 一、盈亏计算器（Profit/Loss）竞品

### 现状盘点

| 产品 | 形态 | 优点 | 问题 |
|---|---|---|---|
| CoinCodex | 网页工具 | 全免费、支持定投/未来预测 | 单币种；费率让用户手填；无多所对比；信息密度高 |
| CoinMarketCap ROI | 内置 portfolio | 币种库最全 | 需账户/持仓数据；ROI 是"历史回溯"非"交易前测算" |
| CoinGecko | 网页工具 | 简单（买价+现价） | 极简，无费用/多所 |
| CoinStats / CoinLedger | 连账户 | 自动算真实持仓 | 需登录/连 API（read-only），隐私门槛高 |
| Good Calculators / Coincalc / CoinProfitTools | 轻量站 | 本地算、免费 | 无多所费率、UI 粗糙、无品牌 |
| 交易所内置（Binance/OKX/Gate） | 平台内 | 绑定持仓实时 | 只算自己平台的交易 |

### 共性痛点（我们的机会）

1. **几乎没人把"各所精确交易费率"算进去**：多数让用户手填一个总费率，甚至忽略；而我们手握 **7 所官方 spot/futures maker/taker 费率**数据层。
2. **没有"同一笔交易在多所的成本对比"**：同样的 1000 USDT 交易，Binance 10 USDT、Kraken 40、Coinbase 60——全网没有工具把这个差异摆出来。
3. **两极分化**：简单工具无深度，深度工具要登录/连账户；**免费 + 精确 + 不登录**的中间态空缺。
4. **无转化场景**：竞品算完就结束，没有"哪家最便宜 → 去注册"的自然引导（对我们反而是优势位）。

## 二、合约清算计算器（Liquidation Price）竞品

### 现状盘点

| 产品 | 覆盖 | 优点 | 问题 |
|---|---|---|---|
| cryptocalk.com | Binance/Bybit/OKX 公式 | 含 MMR、多所公式 | 单所单算，**无多所并排对比**；英文 |
| bitcoinmargin.com | Binance 专用 | 精确到 MMR 分层（cum_b）公式 | 只做 Binance；无对比 |
| regulcrypto.com | 多所 | long/short + 逐仓/全仓 + 多所 MMR 表 + 距离强平% | 单所一次算一个；无费率影响；英文 |
| MEXC 内置 | 自身 | 6 模块含**资金费率** | 只服务 MEXC 用户；登录才能用 |
| Binance/Bybit 官方 | 自身 | 与交易页联动 | 只算自家；全仓动态性说明不足 |

### 共性痛点（我们的机会）

1. **无跨所并排对比**：同一笔合约在 7 所的强平价不同（MMR/维持保证金不同），没人做"并排对比表"。
2. **资金费率几乎全被忽略**：只有 MEXC 提了。实际持仓几天，资金费侵蚀保证金会让**实际强平价比计算值更近**（secret-terminal 明确验证：0.1%/8h 三天扣 0.9%，20x 下等于吃掉 18% 初始保证金）。
3. **全仓模式的"移动目标"问题**：多数工具把全仓强平价当固定值展示，MEXC 官方文章专门吐槽用户把 cross 强平价当"安全底线"而爆仓。
4. **MMR 分层被简化**：`Entry×(1−1/L+M)` 只在 Tier1 准确，大仓位 MMR 分层（bitcoinmargin 强调）。
5. **无中英双语**：全部英文，**海外华人市场空白**。

## 三、我们的差异化方案（怎么做更好）

### 核心差异化：多所并排 + 精确费率 + 双语 + 转化场景

#### T1 盈亏计算器
- **输入**：方向（买/卖）、入场价、数量、出场价（或目标涨幅%）、现货/合约、吃单/挂单
- **输出（杀手锏）**：**7 所并排对比表**——每所精确用其官方费率算净盈亏，最省钱的高亮
  - 例：$10K 现货 taker 一买一卖 → KuCoin/Binance/Bybit 手续费 X，Kraken Y，Coinbase Z → 净盈亏各不同
- **附带**：盈亏率%、回本价、费率吃掉利润的占比
- **转化**：结果表"手续费最低的所"行内 CTA（KuCoin 在其中）+ 底部 sticky（地区过滤）
- **互链**：底部"在 X 交易所交易这币？→ where-to-buy 页"

#### T2 合约清算计算器
- **输入**：方向、入场价、杠杆、仓位价值、逐仓/全仓（全仓需钱包余额）
- **输出**：
  - 7 所并排**强平价 + 距强平幅度%**（MMR 按 Tier1 表内置，标注"大仓位 MMR 分层会变化"）
  - **资金费率预警**：输入预计持仓时长，计算资金费累计对保证金的侵蚀 → "实际安全距离比计算值小 X%"（这是竞品空白）
  - 逐仓 vs 全仓的明确说明（全仓是移动目标，别当固定底线）
- **转化**：结果表行内 CTA（合约费率低的所）+ sticky
- **互链**：→ 合约费率对比页

### 统一工程规范（沿用 tools-roadmap）
- 单文件纯前端 + `window` 数据层（7 所官方费率）+ 中英双语（`.zh.html`）
- 地区过滤（受限地区隐藏 CTA）+ `rel="sponsored"` + disclosure
- 结果区放"公式透明说明"（怎么算的，建立信任 + 利于 GEO 引用）

### 与竞品对比（一句话）

| 维度 | 竞品 | 我们 |
|---|---|---|
| 多所费率精确计算 | ❌ 无 | ✅ 7 所官方费率并排 |
| 跨所对比 | ❌ 单所 | ✅ 并排表 + 最低价高亮 |
| 资金费率影响（清算） | ❌ 几乎无 | ✅ 持仓时长 → 实际安全距离 |
| 中文版 | ❌ 无 | ✅ en + zh |
| 登录/连账户 | 部分要 | ❌ 不需要 |
| 转化场景 | 无 | ✅ 结果区自然 CTA |

## 四、开发顺序与验收

1. **T1 盈亏计算器**（en + zh）：数据层算 7 所净盈亏 → 对比表 → CTA → 互链
2. **T2 合约清算计算器**（en + zh）：强平价并排 + 资金费预警 + 模式说明
3. 验收：可计算、对比正确（用已知样例核对）、地区过滤生效、0 死链、双语完整

> 数据依赖：`exchanges.js`（已有 7 所官方费率）+ 新增 `data/futures_mmr.js`（各所 Tier1 MMR 表，2026-08 调研值：Bybit 0.5%/100x、MEXC 0.4%/200x、OKX 0.5%/125x、Bitget 0.5%/125x、Binance BTC 0.5%… 上线前按各所风险限额页核实）。
